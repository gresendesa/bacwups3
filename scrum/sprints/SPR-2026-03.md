Objetivo: fortalecer o processo de backup depois da base defensiva do restore. A sprint troca o identificador sequencial por ID único, impede sobrescrita silenciosa, trata pacote e manifesto como uma unidade lógica e limita o backup de volumes Docker a montagem somente leitura com imagem versionada definida em um único ponto.

## Scope Boundaries

```yaml

title: Scope Boundaries
status: active
owner: "gresendesa"
created_at: 2026-07-13
updated_at: 2026-07-13
tags: [sprint, scope]
```

Incluído:

* Gerar ID único para cada backup no formato temporal com sufixo aleatório.
* Usar o mesmo ID no pacote e no manifesto.
* Evitar sobrescrita silenciosa no S3.
* Remover pacote remoto quando o envio do manifesto falhar.
* Montar volume Docker de origem como somente leitura.
* Definir imagem Docker versionada em um único local do código.

Fora desta sprint:

* Backup de projeto Git além do comportamento já existente.
* Metadados Git adicionais no manifesto.
* Operação de verificação sem restaurar.
* Suite completa ShellCheck/Bats.

## Implementation Notes

```yaml

title: Implementation Notes
status: active
owner: "gresendesa"
created_at: 2026-07-13
updated_at: 2026-07-13
tags: [sprint, implementation, validation]
```

Implementação concluída e pronta para revisão do PO:

* Backups usam ID único temporal com sufixo aleatório.
* Pacote e manifesto usam o mesmo ID lógico no nome e no campo `backup_id`.
* O backup verifica se pacote ou manifesto já existem no S3 antes de enviar.
* Uploads passam a ser feitos para o URI completo do objeto remoto.
* Falha no upload do manifesto remove o pacote remoto já enviado.
* A imagem Docker usada pelos `docker run` fica centralizada em `DOCKER_BACKUP_IMAGE`.
* Backup de volume Docker monta a origem como `/data:ro`.
