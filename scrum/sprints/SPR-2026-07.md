## Rationale

```yaml

title: Planning Rationale
status: active
owner: "gresendesa"
created_at: 2026-07-13
updated_at: 2026-07-13
tags: [sprint, rationale]
```

* Os fluxos de volume já têm cobertura por mocks, mas ainda não foram exercitados com Docker real.
* O teste real reduz risco operacional antes de usar a ferramenta em volumes críticos.
* O S3 deve permanecer mockado para manter o teste local, determinístico e sem custo externo.
* O risco é alto porque o teste manipula volumes Docker reais e precisa de cleanup robusto.

## Scope Boundaries

```yaml
section: sprint.SPR-2026-07.scope-boundaries
title: Scope Boundaries
status: active
owner: "gresendesa"
created_at: 2026-07-13
updated_at: 2026-07-13
tags: [sprint, scope]
```

Incluído:

* Criar teste de integração para volumes Docker reais com nomes únicos.
* Popular volume de origem com arquivos reais.
* Executar `do_backup volume` com S3 mockado localmente.
* Executar `do_restore volume` para um volume de destino real.
* Comparar conteúdo restaurado com o original.
* Validar montagem read-only do volume de origem.
* Validar rollback real quando a extração falhar.
* Limpar volumes temporários em sucesso, erro ou interrupção.
* Integrar ao runner local de forma segura ou documentar como opt-in quando Docker estiver disponível.

Fora desta sprint:

* Uso de AWS real para este teste.
* Mudanças funcionais no backup/restore de volume, salvo correções necessárias reveladas pelo teste.
* Testes de performance ou grandes volumes.
